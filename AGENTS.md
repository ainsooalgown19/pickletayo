# Development update logging

After each completed development change, update `UPDATE_LOG.md` in the same task.

- Use the current date in Asia/Shanghai; keep newest dates and entries first.
- Write one short bullet per coherent update: what changed, verification result, and any material limitation.
- Record only work actually completed and checks actually run. Label sample data and unverified results accurately.
- Combine related edits from the same task into one entry; avoid file-by-file lists, plans, and routine tool activity.
- Never include credentials, secrets, personal account data, or raw command output.
- For an unfinished change, record the actual partial result and blocker; do not claim completion.
